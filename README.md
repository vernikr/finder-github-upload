# Finder → GitHub Upload

Quick Action для macOS 15: выделите файлы и папки в Finder, отправьте их одной фиксацией в новую папку `vernikr-personal/uploads` и получите ссылку в буфере обмена. Прогресс показывается в Terminal: число **полностью загруженных файлов** и процент от общего количества; это не индикатор байтов. Публикация коммита занимает дополнительное время после 100%.

> **Важно:** если репозиторий `uploads` публичный, каждый, у кого есть интернет, может увидеть загруженные данные. Не отправляйте секреты, персональные данные или материалы, которые нельзя публиковать. Ссылка не является секретной. Сам инструмент рассчитан на конкретный репозиторий, для другого необходимо изменить OWNER и REPO в `upload.py` до установки.

## Установка

1. Скачайте исходный код репозитория через **Code → Download ZIP** или архив исходников релиза; распакуйте. Запускайте только код, который вы проверили и которому доверяете.
2. Откройте `install.command` двойным щелчком. Если появилось **“could not be executed because you do not have appropriate access privileges”**, откройте Terminal, введите `bash ` (с пробелом), перетащите в окно файл `install.command` и нажмите Enter. Это запускает скрипт через bash, даже если у файла потерялся бит исполнения. Если macOS блокирует неизвестного разработчика, посмотрите **System Settings → Privacy & Security** или запустите через Terminal, как описано выше. Запускайте только после проверки источника.
3. Установщик ищет установленный Python 3.12 или новее (версии Python 3), включая Python, управляемый уже имеющимся `uv`. Если подходящий Python найден, скачивать ничего не нужно. Иначе установщик использует существующий `uv` или скачивает и запускает официальный установщик `https://astral.sh/uv/install.sh`; далее `uv` загружает Python 3.12. Не нужны Homebrew, MacPorts, pnpm, Git, Xcode или готовый Python. В зависимости от конфигурации сети могут потребоваться доступ к сайтам Astral и GitHub. Установщик работает от вашего пользователя, `sudo` не нужен. Загружаемый установщик uv исполняется локально; проверьте его заранее, если этого требуют ваши правила безопасности.
4. Выберите **вход через браузер** стрелками ↑/↓ и нажмите Enter. Если терминал не поддерживает стрелки, появится ввод номера. Если GitHub CLI (`gh`) уже установлен, будет использован он; иначе установщик скачает официальный архив последнего релиза GitHub CLI с GitHub, сверит SHA-256 с файлом контрольных сумм из того же релиза и установит только исполняемый файл в каталог приложения. Для этого нужен доступ к GitHub. Это проверка целостности скачивания, а не отдельная проверка подписи.
5. Если `gh` уже авторизован, можно использовать текущую учётную запись. Иначе следуйте подсказкам: CLI покажет одноразовый код и откроет страницу GitHub; введите код и подтвердите запрошенный доступ. Войдите в аккаунт с правом записи в `vernikr-personal/uploads`. Вам не нужно создавать или вставлять PAT. При повторной установке можно выбрать другой способ входа. По завершении и при ошибке окно ждёт Enter; если установка не удалась, скопируйте сообщение об ошибке.
6. Если репозиторий пуст, установщик автоматически создаст в его корне `README.md` и первый коммит. Это нужно для используемого Git Data API; обычный `git push` может инициализировать пустой репозиторий. Существующий README установщик не перезаписывает.
7. Если действие не видно, откройте **System Settings → General → Login Items & Extensions → Extensions → Finder** (названия могут немного отличаться) и включите **GitHub Upload**. При необходимости перезапустите Finder или выйдите из системы и войдите снова.

## Авторизация и безопасность

Вход через браузер использует **OAuth device flow GitHub CLI**: GitHub всё равно выдаёт CLI токен, но вам не нужно его создавать и копировать. GitHub CLI обычно сохраняет учётные данные в Keychain; при невозможности использовать хранилище он может сохранить их **в открытом виде в своём конфигурационном файле**. Проверить способ хранения можно командой `gh auth status`. GitHub CLI запрашивает стандартные OAuth-права, включая `repo` для приватных репозиториев: они шире доступа только к `uploads`. Это общая авторизация GitHub CLI; переключение активного аккаунта или выход из gh может повлиять на инструмент и другие программы, использующие gh. При запрете SSO или защите ветки запрос записи может быть отклонён. Переустановка приложения позволяет выбрать вход заново.

**Альтернатива — персональный токен.** Выберите «Ввести персональный токен» в установщике. Для минимальных прав создайте fine-grained PAT в GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens: Resource owner — `vernikr-personal`, Only select repositories → `uploads`, Repository permissions → Contents: Read and write (Metadata read-only автоматически). Можно также использовать classic PAT с разрешением `repo`, но оно шире. Ввод не отображается; токен сохраняется в Keychain. При сохранении утилита `security` ненадолго получает токен в аргументе процесса, который может быть виден другим локальным процессам. Не помещайте токен в файлы и публичные чаты. Тест права записи не отменяет ограничений защищённой ветки.

## Разрешения macOS

* При первом запуске macOS может запросить разрешение для Automator/Finder управлять **Terminal**: разрешите. Если отказали, включите в **System Settings → Privacy & Security → Automation** для приложения, показанного в запросе.
* Доступ к Desktop, Documents, Downloads и съёмным дискам может запрашиваться отдельно. Разрешите доступ для Terminal или другого приложения, указанного в диалоге, в **Privacy & Security → Files and Folders**. Если этого недостаточно, можно точечно выдать Terminal **Full Disk Access**, понимая, что это расширенный доступ ко всем файлам; обычно он не нужен.
* Keychain может попросить разрешить чтение сохранённого токена. При отказе загрузка не выполнится.
* Системные сообщения отличаются в зависимости от версии и языка macOS. Finder Quick Action работает от имени текущего пользователя.

## Использование

Выделите в одной папке Finder файлы и/или папки → правый клик → **Quick Actions / Быстрые действия → GitHub Upload**. Откроется Terminal с прогрессом. После публикации появится диалог, а ссылка на новую папку скопируется в буфер. Окно Terminal можно закрыть нажатием Enter. При ошибке она выводится в Terminal; операция не считает себя успешной и ссылку не копирует.

Структура выбранных папок, включая скрытые файлы, и имена сохраняются внутри новой уникальной папки. Пустые папки Git не хранит; символьные ссылки и специальные файлы намеренно отклоняются, в том числе внутри папок. Файлы размером больше 50 МиБ не принимаются. Данные считываются в память и передаются GitHub API целиком по одному файлу; для больших наборов процесс может быть медленным. Бинарные и пустые файлы поддерживаются. Файлы, меняющиеся во время загрузки, не гарантированно образуют снимок.

Прогресс идёт по загруженным blobs; изменения становятся видны только после записи одного коммита в default branch. При изменении ветки другим участником инструмент делает до трёх попыток без force push. Если сеть оборвётся непосредственно после обновления ссылки на ветку, результат может быть неопределённым — проверьте репозиторий прежде чем повторять. Прерванная загрузка может оставить недоступные из веток Git blobs до их очистки GitHub.

## Удаление

Запустите `uninstall.command` или в Terminal введите `bash `, перетащите файл `uninstall.command` в окно и нажмите Enter. Оно удалит Quick Action, установленные файлы, локальную копию gh и PAT из Keychain. Установленные отдельно uv и Python остаются. Авторизация GitHub CLI является общей и при удалении приложения **не удаляется**; для выхода из неё используйте `gh auth logout` (это влияет и на другие приложения, использующие gh). OAuth-доступ можно отозвать в GitHub → Settings → Applications → Authorized OAuth Apps. PAT можно отозвать отдельно в настройках GitHub.

## Разработка

`python3 -m unittest discover -s tests -v` запускает локальные тесты без доступа к GitHub. Установка, системные разрешения и Finder требуют проверки на реальном macOS 15. Исходный формат Automator собирается из системного action bundle; формат пакета и метаданные вдохновлены проектом [AutoAutomator](https://github.com/fullac/AutoAutomator).
